# 2026-11-17 接口调整说明

本次对应需求编号 1～7、9～15，无数据库结构变更。以下接口沿用现有 ApiResponse 外层结构和 userId 请求头。

## 任务修改并发起流程（第 2 项）

`PUT /tasks/{taskId}`

仅设计者可以操作，任务须处于 DRAFT 或 PENDING_INITIATION；进行中的任务须先撤回。
修改成功后按创建任务的规则进入初始评审阶段，刷新待办并记录流程日志。

```json
{
  "projectNo": "P-001",
  "projectName": "BMS项目",
  "files": ["文件UUID"],
  "reviewRoles": ["PCB_EXPERT", "EMC_EXPERT"],
  "reviewerAssignments": [
    {"reviewRole": "PCB_EXPERT", "reviewerEmployeeNos": ["员工工号1"]},
    {"reviewRole": "EMC_EXPERT", "reviewerEmployeeNos": ["员工工号2"]}
  ],
  "expertLeaderEmployeeNo": "组长工号"
}
```

- 新增的 reviewRoles、reviewerAssignments、expertLeaderEmployeeNo 可省略，省略沿用原值。
- 草稿首次发起正常发送邮件；待发起任务本次修改中专家分配未变，不重复发送。
- 分配按“角色＋工号”集合比较，调整顺序不会触发重复邮件；组长变化也会触发通知。
- 分配变更邮件通知本次初始阶段的收件人，正文增加：
  “本任务已撤回并重新发起，专家分配已调整。请以本次通知及系统中的最新任务信息为准，重新开展评审。”

## 我的任务（第 7、13 项）

`GET /tasks/my`

参数与任务列表一致：taskName、projectNo、projectName 模糊查询；designerId 为设计者工号精确查询；reviewType 为评审类型；statuses 支持多个同名参数；pageNum 默认 1，pageSize 默认 20、最大 100。

响应 data 由数组改为分页对象，前端从 `data.items` 取列表：

```json
{"total": 1, "pageNum": 1, "pageSize": 20, "items": [{"id": 1001, "designerAction": "WITHDRAW"}]}
```

示例省略其他原有字段。designerAction 与任务列表使用相同规则：WITHDRAW 可撤回、TERMINATE 可终止、NONE 无操作。我的任务仍只返回当前用户的待办，过滤在分页前执行。

## 多类型批量上传（第 12 项）

`POST /files/upload/grouped`，Content-Type 为 multipart/form-data。

- `taskId`：任务 ID。
- `fileCategories`：可重复传入的文件类型参数。
- 文件 part 名使用类型编码，每个类型可对应多个同名 part。

前端示例：

```javascript
const form = new FormData();
form.append('taskId', taskId);
form.append('fileCategories', 'PCB_REVIEW');
form.append('fileCategories', 'PCB_STRUCTURE_REVIEW');
form.append('PCB_REVIEW', pcbFileA);
form.append('PCB_REVIEW', pcbFileB);
form.append('PCB_STRUCTURE_REVIEW', structureFile);
```

返回 data 按类型分组：

```json
[
  {"fileCategory": "PCB_REVIEW", "files": [{"fileId": "文件UUID", "taskFileId": 101, "fileName": "a.pcb", "fileSize": 100, "fileCategory": "PCB_REVIEW"}]},
  {"fileCategory": "PCB_STRUCTURE_REVIEW", "files": [{"fileId": "文件UUID", "taskFileId": 102, "fileName": "b.zip", "fileSize": 200, "fileCategory": "PCB_STRUCTURE_REVIEW"}]}
]
```

每类至少一个非空文件，类型不能重复，文件字段名须与类型列表一致。各类本批次文件全部作为最新文件，原同类型最新文件转为历史。整批数据库登记处于同一事务；原单类型上传接口继续保留。

## 邮件（第 1、15 项）

- 硬件部门抄送改为 reviewer_whitelist 中未删除、department_name 为“BMS硬件开发部”的人员邮箱，不再使用固定部门邮箱。
- 跳过空邮箱，按去除首尾空白且忽略大小写的邮箱去重。
- 包含 EMC 评审时，继续合并 roles 包含完整角色码 EMC-LEADER 的人员。
- 正文称呼按实际收件人数决定：一人“您好”，多人“你们好”，抄送人数不参与计算。

## 权限及流程（第 3～6、9～11、14 项）

- 所有登录用户可查询任务列表、详情、最新文件和下载任务文件；上传和取消上传仍校验设计者身份。
- 同时开启工艺、结构评审，只生成一条流程日志：action_name、flow_comment 均为“开启工艺结构评审”，从 PCB_EXPERT_REVIEWING 进入 PCB_PROCESS_STRUCTURE_REVIEWING。两个分支的人员均进入待办。
- requireFinalFile 删除无实际作用的意见更新时间比较；仍要求存在设计者在当前评审阶段上传的最新终版文件。
- 模板大类按照父级是否为 Sheet 识别，支持第二级大类修改及其小类增删改。
- PCB 退回专家评审后，历史意见保留；本轮待办中的专家均显示为未提交，须重新确认提交后才能继续推进。
- 意见列表原 sourceType/sourceTypes 参数支持 MUTUAL_CHECK_ITEM；该来源意见确认通过时，在同一事务将其 sourceItemId 对应的任务互检项设为 PASS，保留原说明。
- “以下评审人尚未确认提交”显示人员姓名，资料缺失时提示“姓名未维护”，不直接显示工号。
- START_SCHEMATIC_EXPERT_ASSIGNMENT 要求存在 is_latest=true 的 SCHEMATIC_REVIEW 文件，无文件提示“请先上传最新原理图评审文件”。
