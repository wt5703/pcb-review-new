## 1. 产品概述

### 1.1 背景与问题

当前 PCB、原理图评审涉及设计者、组长、专家、工艺与结构人员，常通过线下文件、邮件或聊天工具流转。问题、修改答复和最终文件版本容易脱节，且难以确认每位参与者是否已经完成评审。

平台用于在线创建和流转评审任务，围绕同一任务沉淀文件版本、人员分配、评审意见、设计者答复、专家确认及操作记录，形成可追溯的评审闭环。

### 1.2 产品目标

- 标准化 PCB 与原理图的评审流程。
- 使每条评审意见均可答复、确认和追溯。
- 明确任务当前阶段、参与人员和完成情况。
- 保证评审结论关联明确的文件版本。
- 在任务创建、开启工艺/结构评审和任务结束等关键节点发送邮件。

### 1.3 非目标

- 本期不建设 CAD/PCB 在线编辑或自动 DRC 检查能力。
- 本期不建设独立的“评审执行域”或“评审单”对象；专家评审、工艺评审、结构评审和互检均属于评审域。
- 本期不实现通用消息中心；仅实现约定的邮件通知场景。
- 本期不自行建设底层文件存储，文件服务通过公司文件 API 对接。

## 2. 用户与角色

| 角色 | 主要职责 |
| --- | --- |
| 设计者 | 创建任务、上传/关联文件、答复意见、查看任务进度 |
| PCB 组长 | 分配 PCB 专家、发起 PCB 互检、确认 PCB 任务结束 |
| 原理图组长 | 发起原理图互检、确认原理图任务结束 |
| 硬件开发部经理 | 为原理图任务指定硬件专家 |
| PCB/原理图专家 | 对已分配任务提出意见、确认答复 |
| 硬件/EMC 专家 | 对原理图任务提出意见、确认答复；EMC 专家可下载 PCB/原理图文件 |
| 工艺/结构专家 | 对已开启并分配的 PCB 任务提出意见、确认答复 |

“查看任务”与“处理任务”分开控制。除工艺专家、结构专家外，其他角色可查看全部任务；工艺专家和结构专家仅可查看被分配或与其职责相关的任务。评审、分配、结束等会改变任务流程的操作，仍必须按角色权限和当前流程节点校验。

## 3. 业务范围与领域边界

| 模块/域 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 评审任务域 | 任务创建、查询、整体状态、归档、结束 | 意见处理、文件存储、具体权限判定 |
| 评审域 | 人员分配、专家/工艺/结构评审、互检、意见答复和确认 | 任务创建、文件版本管理、整体流程编排 |
| 文件与版本域 | 文件元数据、上传、MD5、版本链、最新版本标识 | 评审结论、阶段准入、权限策略 |
| 身份与权限域 | 用户、角色、功能权限、数据权限、文件权限 | 评审流程与意见生命周期 |
| 流程与状态编排 | 阶段准入判断、状态推进、结束条件计算 | 创建意见、上传文件等具体业务动作 |
| 通知域 | 业务事件监听、邮件模板、收件人、发送记录和重试 | 业务状态流转 |
| 操作审计能力 | 操作记录、前后值、结果、归档快照 | 业务规则判断 |

### 3.1 评审人员处理关系

不创建“评审单”。评审域维护任务与评审人员的关联关系，用于说明“谁负责什么、是否完成”。

字段包括：任务、评审类型/角色、评审人员、分配人、分配时间、处理状态、开始时间、提交时间、关联文件版本、无意见声明。

处理状态：`待评审`、`评审中`、`已提交`、`已完成`。其中“已提交”表示评审人员已声明本次评审完成，可能有意见，也可能无意见；是否能够进入下一阶段由流程编排判断。

## 4. 核心业务对象

### 4.1 评审任务

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 必填，支持模糊查询 |
| 项目名称 | 必填，支持模糊查询 |
| 评审类型 | PCB 布局布线评审 / 原理图评审 |
| 设计者 | 页面显示名称，接口保存用户 ID |
| PCB/原理图名称 | 根据评审类型显示对应字段 |
| PCB 类型 | BMU 板、BSU 板、分流器板、高压板、转接板、储能板、其他；仅 PCB 评审必填 |
| 评审角色 | 硬件、EMC、结构、工艺、PCB，可多选 |
| 专家/组长 | 按评审类型指定对应人员 |
| 基本描述 | 任务背景、评审重点和补充说明 |
| 期望完成时间 | 用于任务排期与逾期标识 |
| 状态 | 见第 5 章 |
| 创建人/创建时间 | 系统记录 |

创建页面点击“保存任务”时允许暂存不完整信息，状态为“待提交”；提交前须完成必填字段及初始评审文件关联。

### 4.2 文件与版本

文件类型可包括 PCB、原理图、Gerber、BOM、3D/结构资料、工艺资料、问题截图及其他附件。每个文件包含：文件名、类别、大小、MD5、版本号、上传人、上传时间、公司文件服务 ID、是否最新版本。

同一任务内，同一文件类别和业务文件标识形成版本链；同一版本链只能有一个最新版本。MD5 与最新版本相同时，提示用户文件内容重复，不创建新版本。

评审人员开始处理时，系统记录其关联的文件版本；后续上传新版本不会自动改变已开始评审的依据。设计者在答复意见时可明确关联本次修改对应的文件版本。

### 4.3 评审意见

所有问题统一采用 `ReviewOpinion` 模型，来源可以是专家、工艺、结构、互检固定检查项或互检额外意见。

| 字段 | 说明 |
| --- | --- |
| 来源 | 评审类型及关联的检查项（如有） |
| 问题等级 | 严重、主要、一般；具体定义见第 9 章 |
| 问题内容 | 必填 |
| 问题截图/附件 | 可选，支持多份 |
| 提出人/提出时间 | 系统记录 |
| 文件版本 | 提出意见时所依据的版本 |
| 当前状态 | 待答复、待确认、确认通过、确认不通过、已撤回 |
| 答复记录 | 每次答复、说明、关联文件版本、答复人及时间 |
| 确认记录 | 每次确认结果、说明、确认人及时间 |

## 5. 任务状态与流程

### 5.1 PCB 评审任务状态

`待提交 → 待评审 → 专家评审中 → 工艺/结构评审中（可选） → 待分配互检 → 互检中 → 待确认结束 → 已结束`

工艺与结构评审为可选项，可同时进行。若两者都未开启，专家评审完成后可直接进入“待分配互检”。

### 5.2 原理图评审任务状态

`待提交 → 待分配互检 → 互检中 → 待评审 → 硬件评审中 → 待确认结束 → 已结束`

“硬件评审中”可包含硬件专家、EMC 专家和其他被指定专家的并行处理。

### 5.3 阶段准入规则

| 当前动作 | 准入条件 |
| --- | --- |
| 提交任务 | 必填任务信息完整，至少关联一份相应的初始设计文件 |
| 开启 PCB 工艺/结构评审 | PCB 专家评审完成，且组长选择开启对应评审 |
| 进入 PCB 互检 | PCB 专家及所有已开启的工艺/结构评审人员均已提交；其意见均确认通过或无意见 |
| 进入原理图专家评审 | 原理图互检人员已提交；互检意见均确认通过或无意见 |
| 进入待确认结束 | 当前流程要求的所有人员已提交，所有相关意见均确认通过或无意见，且存在最新设计文件 |
| 结束任务 | 处于待确认结束，且由对应组长执行确认 |

任务域负责保存整体状态；流程与状态编排负责计算是否满足转移条件，并发起状态推进。

## 6. 功能需求

### 6.1 任务管理

1. 创建人可创建 PCB 或原理图评审任务，保存为草稿或提交。
2. 支持按任务名称、项目名称、设计者名称模糊查询；支持按评审类型、任务状态筛选。
3. 任务详情展示基础信息、当前流程阶段、参与人完成情况、文件版本、意见统计、流转记录和邮件记录。
4. “我的任务”仅展示当前流程节点需要当前用户执行动作的任务：需要本人评审、答复、确认意见、分配人员或确认结束的任务；它不是“我创建的任务”或“我可以查看的全部任务”。
5. 任务关闭后进入只读归档状态，不允许重新打开；任务结束后不得继续修改业务数据。

### 6.2 人员分配与评审

1. 创建 PCB 任务时指定 PCB 专家；创建原理图任务时指定原理图组长。
2. PCB 组长可在满足条件后分配互检人员、开启并分配工艺/结构评审。
3. 原理图组长可分配互检人员；互检完成后，硬件开发部经理指定硬件专家及其他专家。
4. 被分配人员可查看关联任务及已授权文件，开始评审后状态变为“评审中”。
5. 评审人员可提交意见，或在无问题时提交“无意见”。提交后不再允许无记录地修改；如需补充，新增意见或由流程允许重新处理。
6. 支持改派和追加人员。改派必须记录原人员、目标人员、原因和时间；已经提交的历史意见保留。
7. 同一评审角色可分配一人或多人；分配多人时，全部人员均已提交且其相关意见均闭环后，才视为该角色评审完成。

### 6.3 互检

1. 互检基于检查项模板生成任务内检查项，不生成独立评审单。进行中的已创建任务跟随模板后续变化；已完成任务的检查项固定，不再跟随模板变化。
2. 检查项支持目录层级、检查结果（合格/不合格/不适用）、图片和说明。
3. 检查结果为“不合格”时必须填写说明，并自动或手动关联一条评审意见；避免检查项问题与意见闭环脱节。
4. 互检人员可提出检查项外的额外评审意见。
5. 标记“不适用”时必须填写原因。

### 6.4 意见闭环

1. 评审人员提出意见后，状态为“待答复”。
2. 设计者可选择“接受”“接受但不修改”“不接受”，后两者必须填写原因；答复后状态为“待确认”。
3. 选择“接受”时可关联修改后的文件版本；系统不得强制要求每条意见都产生新文件。设计者重新上传版本后，仅进入该意见的答复确认，由意见提出人确认通过或不通过；不自动触发已完成角色的重新评审。
4. 意见提出人可确认通过或不通过。确认不通过后意见回到“待答复”，保留全部历史答复与确认记录。
5. 意见提出人可撤回本人尚未关闭的意见，并填写撤回原因。撤回后的意见不计入未闭环数量，但须保留审计记录。
6. 任务内意见列表支持按来源、问题等级、状态、提出人筛选；看板展示待答复、待确认、确认不通过、确认通过和已撤回数量，以及每位评审人员的处理进度。

### 6.5 文件管理

1. 通过公司文件 API 上传、预览、下载文件；平台仅保存文件元数据和关联关系。
2. 上传同一业务文件的新内容时生成版本号；重复 MD5 文件提示并由用户决定是否取消关联。
3. 任务详情可查看各类文件的版本历史和当前最新版本。
4. 文件预览、下载、上传均进行角色权限和任务数据范围校验，禁止仅通过修改 `fileId` 绕过权限。
5. EMC 专家可下载 PCB/原理图文件，用于开展评审；其他角色的下载范围按第 7.1 节权限矩阵执行。

### 6.6 通知

| 事件 | 是否发送邮件 | 说明 |
| --- | --- | --- |
| PCB 任务创建成功 | 是 | 通知相关人员 |
| 开启 PCB 工艺评审前 | 是 | 通知工艺相关人员 |
| 开启 PCB 结构评审前 | 是 | 通知结构相关人员 |
| PCB 任务结束 | 是 | 通知相关人员 |
| 原理图任务创建成功 | 是 | 通知相关人员 |
| 原理图任务结束 | 是 | 通知相关人员 |

业务模块只发布明确业务事件，例如 `PCB_TASK_CREATED`、`PCB_PROCESS_REVIEW_STARTING`、`PCB_TASK_FINISHED`。通知域根据事件匹配模板和收件人，记录发送结果，并对失败发送进行重试。邮件失败默认不阻断业务状态流转，但在管理端可见。

## 7. 权限与安全要求

1. 后端对每个读取和写入接口进行角色权限及任务数据范围校验，前端隐藏按钮不作为安全控制。
2. 查看范围按第 7.1 节执行；需要处理当前流程节点的操作，必须进一步校验当前用户是否为该节点的授权处理人。
3. 所有涉及 `taskId`、人员关联 ID、`opinionId`、`fileId` 的接口，均校验当前用户是否对目标对象具备相应权限，禁止通过修改 ID 越权。
4. 用户禁用后不得登录或执行新操作；其历史任务、意见和审计记录必须保留。
5. 任务结束后，设计文件、意见和流转记录生成归档快照，以保证后续可追溯。

## 8. 审计与归档

系统记录创建、提交、状态变更、人员分配/改派、评审开始/提交、意见新增/答复/确认/撤回、文件上传/下载、任务结束及邮件发送等操作。

审计记录至少包括：操作人、操作时间、操作类型、业务对象类型和 ID、操作结果、必要的前后值、失败原因（如有）。

任务归档记录至少包括：任务最终状态、最终关联文件及 MD5、参与人完成情况、全部意见及处理结论、流程流转意见、邮件发送记录。

## 10. MVP 验收标准

1. 设计者能创建、暂存并提交 PCB 或原理图任务，任务信息和初始文件可完整查询。
2. 不同角色只能看到和操作被授权的任务、意见和文件。
3. 组长/经理能依照流程分配相应人员，系统能显示每位人员的未开始、处理中、已提交状态。
4. 专家和互检人员能创建意见；设计者能答复；提出人能确认，且全过程可追溯。
5. 互检支持固定检查项及额外意见；不合格检查项不能在没有关联意见或明确豁免说明的情况下完成。
6. 系统仅在满足阶段准入条件时允许进入下一阶段或结束任务。
7. 文件新版本、MD5、最新版本和意见关联版本均可正确查询。
8. 六类约定邮件事件均产生可查询发送记录；失败发送可重试且不造成重复业务数据。
9. 所有关键操作都留有审计日志；已结束任务可查看完整归档信息。
