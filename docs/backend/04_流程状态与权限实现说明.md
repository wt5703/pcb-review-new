# PCB 评审平台流程状态与权限实现说明

## 1. 实现目标

本文件把 PRD 已确认的流程与权限要求转换为后端校验点，不新增业务规则。唯一状态来源是 `review_task.status`；评审人员处理状态和意见状态独立保存，不能混入任务状态字段。

## 2. 流程实现模型

`WorkflowService` 提供只读判断和状态推进申请：

```text
evaluateAvailableActions(task, currentUser)
evaluateTransition(task, action)
transition(taskId, action, currentUser, version)
```

每个转换必须在事务内重新计算条件，不能相信前端先前查询的“可操作”结果。转换成功后写入 `task_flow_record`、`audit_log` 和必要的 Outbox 事件。

## 3. 任务状态转换表

| 任务类型 | 动作 | 主要前置条件 | 执行结果 |
| --- | --- | --- | --- |
| PCB | 提交 | 提交字段与初始文件满足 PRD | 待提交 → 待评审/专家评审中（按 PRD 状态配置） |
| PCB | 开启工艺/结构评审 | PCB 专家已完成，操作者具备权限 | 创建对应人员关系，进入工艺/结构评审中；写邮件事件 |
| PCB | 分配互检 | PCB 专家及所有已开启角色均完成，相关意见已闭环/无意见 | 待分配互检 |
| PCB | 提交互检 | 互检人员全部完成，相关意见已闭环/无意见 | 待确认结束 |
| PCB | 结束 | 最新设计文件存在，全部必需角色完成，意见满足 PRD，操作者有结束权限 | 已结束并归档 |
| 原理图 | 提交/分配互检 | 任务已提交且操作者有权限 | 待分配互检 → 互检中 |
| 原理图 | 分配专家 | 互检人员全部完成，相关意见已闭环/无意见 | 待评审/硬件评审中 |
| 原理图 | 结束 | 最新设计文件存在，全部必需角色完成，意见满足 PRD，操作者有结束权限 | 已结束并归档 |

具体初始状态的显示文案以 PRD 最终状态表为准；代码采用枚举和状态配置，不在 Controller 中散落字符串判断。

## 4. 完成条件算法

1. 查询当前阶段全部必需 `task_reviewer` 记录。
2. 任一记录非 `SUBMITTED`/`COMPLETED`，阶段未完成。
3. 对每位必须完成者关联的未撤回意见，存在非“确认通过”的意见则阶段未完成；“无意见”提交视为该人员完成。
4. 同一角色有多人时，全部处理关系均满足以上条件后才算角色完成。
5. 结束任务前额外验证存在最新设计文件和 PRD 要求的全部阶段完成。

算法应封装为可单元测试的 `CompletionPolicy`，由状态推进和“可执行动作”查询复用，避免两处判断不同。

## 5. 权限实现

权限判断拆为四层：

| 层级 | 问题 | 实现位置 |
| --- | --- | --- |
| 身份 | 当前用户是谁、是否启用 | 安全上下文/身份适配 |
| 功能权限 | 是否具备创建、分配、答复、结束等功能 | `PermissionService` |
| 数据范围 | 能否看见任务、意见和文件 | Repository 查询条件 + 服务端对象校验 |
| 节点权限 | 当前流程是否正好由此人处理 | `WorkflowService` + `task_reviewer` 校验 |

查询接口也必须应用数据范围。除工艺专家、结构专家外的全量任务可见规则，以及 EMC 专家可下载设计文件规则，由 `PermissionService` 使用 PRD 权限矩阵配置实现；不要仅依赖前端菜单。

## 6. 写接口通用保护

```text
认证用户
  → 加载对象（带数据范围）
  → 校验功能权限
  → 校验当前状态/意见状态
  → 校验节点处理人或管理权限
  → 校验 version 与幂等键
  → 事务写入业务数据、流转记录、审计和 Outbox
```

使用 ID 获取对象时不得直接按主键查询后返回；必须通过带数据范围的仓储方法或在应用服务中做归属校验。任何跨任务替换 `taskId`、`opinionId`、`fileId`、人员关系 ID 的请求必须失败。

## 7. 结束与归档

结束动作必须串行化或使用乐观锁，只允许一个请求成功。成功后：

1. 更新任务至已结束。
2. 生成任务、文件版本、人员完成情况、意见与邮件记录的归档快照。
3. 写流程记录、审计记录及“任务结束”Outbox 事件。
4. 后续写接口统一拒绝已结束任务；不提供重新打开接口。
