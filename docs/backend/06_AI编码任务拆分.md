# PCB 评审平台 AI 编码任务拆分

## 任务拆分原则

每个任务按一个业务垂直域交付：领域规则、数据库迁移、应用服务、REST 接口、权限校验、审计/事件影响和自动化测试同时完成。后续任务只能依赖已完成任务公开的接口与数据模型。

## 已实施任务记录

### 任务 1：评审任务域（进行中，约 95%）

- 已交付：评审任务草稿创建、提交、详情与列表接口；任务名称、项目名称、设计者、类型、状态筛选与分页；`review_task` 持久化和重启后恢复；创建/提交审计记录；提交 Outbox 事件；应用、持久化和 REST 自动化测试。
- 已补充：工艺/结构专家仅可见有效的 `task_reviewer` 关联任务；改派后 `CANCELLED` 历史人员不再作为数据范围授权来源。
- 未完成：任务结束/归档后的最终只读联调验收依赖任务 6。

### 任务 2：身份与权限域（进行中，约 60%）

- 已交付：请求头 Mock 身份；角色与功能权限矩阵；文件上传/下载权限；EMC 专家下载 PCB/原理图文件的用户确认例外；受限专家按任务分配的数据范围判断；当前节点处理人通用校验；现有创建任务接口的越权测试。
- 未完成：评审、文件与流程写接口完成后统一接入节点校验，并覆盖跨对象越权集成测试。

### 任务 3：文件与版本域（已完成）

- 已交付：本地上传会话 Mock；`review_file` 文件元数据及版本链持久化；MD5 重复识别；新版本递增；受控下载地址；权限校验；文件版本与下载授权自动化测试。
- 已知实现边界：本地阶段只生成 `mock://` 上传和下载地址，不保存文件二进制；后续替换为公司文件 API 适配器。

## 当前执行任务：任务 4（评审域：人员与互检）

本任务实现评审域中的人员关系与互检处理：分配、改派、处理进度、无意见提交、检查项实例和额外意见入口。不实现设计者答复、评审人确认、任务最终结束或文件二进制存储；这些由后续任务负责。

### 本轮已完成内容（2026-09-17）

- 新增 `task_reviewer` 的人员分配、改派（保留 `CANCELLED` 历史）、当前人员无意见提交、人员查询 REST 接口；所有分配均按角色矩阵校验。
- 同一职责存在多位评审/互检人员时，`areAllReviewersSubmitted` 只会在所有有效人员均为已提交或已完成时返回完成。
- 新增检查项模板、任务内检查项快照及 Flyway V5；进行中任务每次读取/提交时按当前启用模板同步，`FINISHED` 状态的任务仅读取已有快照。
- 新增检查项查询、提交和本地模板新增/修改接口；进行中任务在下次读取或提交时同步模板名称、层级、排序和启用状态，不合格/不适用必须填写说明，不合格还要求提交关联意见标识。关联意见的真实归属验证将在任务 5 接入。
- 已新增人员多人完成、检查项模板物化和不合格约束的自动化测试；本轮代码已通过全量 Maven 测试。

### 验收条件

1. 按 PCB/原理图流程权限分配、改派评审人员和互检人员，并写入 `task_reviewer`。
2. 被分配人员可查看关联任务；“我的任务”仅返回当前节点需要其评审、分配、确认或结束的事项。
3. 评审人员可提交意见或“无意见”；同一角色多人时，必须全部提交才算该角色处理完成。
4. 互检支持任务内固定检查项实例和额外意见；已创建未完成任务的检查项随模板变更更新，已结束任务保持快照不变。
5. 自动化测试覆盖改派、无意见、多人全员完成、未分配越权和检查项规则。

## 进度快照（2026-09-17）

当前全量自动化测试已通过。任务 1 的分页筛选、审计/Outbox 和接口测试已补齐；工艺/结构专家的“授权范围”数据模型依赖任务 2 的角色矩阵与授权关系，因此任务 1 暂不标记为完成。任务 2、3、5、6 中出现的领域基础代码不等同于对应任务完成，必须同时满足表中的完成标准。

任务 5 已于本轮启动：Flyway V6 已增加意见答复与确认历史表，意见接口已支持在设计者重新上传关联版本后，仅对该条答复执行通过或不通过确认；不会重新分配或重启评审流程。已补充互检额外意见及设计者答复、提出人确认的应用层自动化测试。

任务 6 已于本轮启动：Flyway V7 新增流程历史；流程服务在事务内校验状态、权限、任务版本、所有有效评审人员提交及其意见闭环、最新文件，并在结束前同步检查项快照。结束后统一拒绝重新打开或再次流转。
