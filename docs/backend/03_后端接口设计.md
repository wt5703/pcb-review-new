# PCB 评审平台后端接口设计

## 1. 通用约定

- 基础路径：`/leapmotor/pcb_review`。
- 认证：由公司统一身份认证接入；Controller 从安全上下文读取当前用户，不接受客户端传入 `operatorId`。
- 写请求建议带 `Idempotency-Key`；响应带 `traceId`。
- 分页请求：`page`（从 1 开始）、`size`（最大值由配置控制）、`sort`。列表响应包含 `items`、`page`、`size`、`total`。
- 所有接口使用 DTO，不直接暴露数据库实体。枚举同时返回 `code` 和可展示的 `name`。

统一错误响应：

```json
{"code":"TASK_STATUS_CONFLICT","message":"当前任务状态不允许此操作","traceId":"..."}
```

## 2. 接口清单

| 模块 | 方法与路径 | 用途 |
| --- | --- | --- |
| 任务 | `POST /tasks/save` | 创建或保存草稿任务 |
| 任务 | `POST /tasks/submit` | 创建或提交任务 |
| 任务 | `GET /tasks` | 分页查询、筛选任务 |
| 任务 | `GET /tasks/my` | 查询当前节点需本人处理的任务 |
| 流程 | `POST /tasks/{id}/workflow/transitions` | 一次编排阶段文件登记、人员分配和流程状态推进 |
| 流程 | `GET /tasks/{id}/workflow/reviewers?role=...` | 查询当前职责已分配人员 |
| 意见 | `POST /tasks/{id}/opinions` | 提出评审意见 |
| 意见 | `GET /tasks/{id}/opinions?pageNo=1&pageSize=20` | 分页查询、筛选意见；返回 `total`、`pageNo`、`pageSize`、`items` |
| 意见 | `GET /opinions/{id}` | 查询意见详情及历史 |
| 意见 | `POST /opinions/{id}/reply` | 设计者答复意见（`/replies` 暂时兼容） |
| 意见 | `POST /opinions/{id}/confirm` | 提出人确认答复（`/confirmations` 暂时兼容） |
| 意见 | `POST /opinions/{id}/withdraw` | 提出人撤回意见 |
| 互检 | `GET /tasks/{id}/check-items` | 查询任务内检查项 |
| 互检 | `PUT /tasks/{id}/check-items/{itemId}` | 提交检查结果与说明 |
| 文件 | `POST /files/upload` | 上传二进制到公司资源服务；无任务时仅允许创建任务文件并返回 UUID，有任务时立即登记元数据 |
| 文件 | `GET /files/latest?taskId=...&fileCategory=...` | 查询任务当前文件 |
| 文件 | `POST /files/download?taskId=...&fileId=...` | 按任务和唯一文件 ID 代理下载已登记文件；后端根据文件记录校验类别权限 |

## 3. 核心请求约束

### 3.1 创建任务 `POST /tasks/save`、`POST /tasks/submit`

请求包含任务名称、项目名称、评审类型、设计者、设计名称、描述、期望完成时间、PCB 类型（如适用）、评审角色及初始关联文件。创建草稿可缺少提交必填项；提交接口必须做完整校验。

### 3.2 流程编排 `POST /tasks/{id}/workflow/transitions`

请求必须包含 `action`，可选包含 `comment`、`assignedRole`、`reviewerIds` 和 `stageFiles`。控制器按业务动作拆分为人员分配、工艺/结构评审开启、管理员结束和常规节点推进四类分支，再由应用服务在一个事务中校验并处理：

- `START_PCB_OPTIONAL_REVIEW` 可附 `PROCESS_REVIEW` 场景的文件引用。文件二进制必须先由 `POST /files/upload` 上传至公司资源服务；流程接口只登记公司返回的唯一标识和元数据，然后校验前序意见均已确认通过并进入工艺/结构评审。
- `START_PCB_MUTUAL_REVIEW` 必须同时传 `assignedRole=PCB_MUTUAL_CHECK` 和至少一名 `reviewerIds`，由 PCB 组长分配组员并开启互检。
- `START_SCHEMATIC_MUTUAL_REVIEW` 必须同时传 `assignedRole=SCHEMATIC_MUTUAL_CHECK` 和至少一名 `reviewerIds`，由原理图组长分配组员并开启互检。
- `START_SCHEMATIC_EXPERT_REVIEW` 必须同时传 `assignedRole=SCHEMATIC_HARDWARE_EXPERT` 或 `SCHEMATIC_OTHER_EXPERT` 和至少一名 `reviewerIds`，由硬件开发部经理分配专家并开启原理图评审。
- `SUBMIT_NO_OPINION` 由当前评审人通过本流程接口提交，不接收人员或文件参数；它只将本人标记为已完成且无意见，不改变任务状态。`FINISH` 不需要附加参数，按当前结束权限直接确认结束；常规节点推进同样不能夹带人员分配或阶段文件，避免跨节点写入。创建任务使用任务保存/提交接口；互检单、原理图等二进制文件上传使用文件接口，不作为流程推进请求的一部分。

响应包含 `fromStatus`、`toStatus`、本次 `assignedReviewers` 与本次登记的 `stageFiles`。人员查询和“无意见”操作统一位于 `/tasks/{id}/workflow/reviewers` 下；不再保留独立 `ReviewerAssignmentController` 或改派接口。

### 3.3 意见答复与确认

答复请求仅包含 `replyType`、`reason`。确认请求包含 `passed`、`comment`。意见及答复不关联文件版本；服务端校验意见当前状态、答复人资格和确认人资格，不得由客户端直接提交目标意见状态。

### 3.4 文件接口

上传文件保存为当前业务文件；同一任务、类别和业务文件键再次上传时直接替换当前文件，不维护版本号或版本链。下载接口只返回受控下载地址，不透传永久存储地址。

## 4. 授权校验模式

每个写接口按固定顺序校验：

1. 用户已认证且账号有效。
2. 用户具备对应功能权限。
3. 用户对目标任务/意见/文件处于允许的数据范围。
4. 当前任务状态和节点允许该操作。
5. 用户是该节点的被分配处理人，或具有 PRD 明确的管理/结束权限。
6. 写接口不要求任务或文件版本号；当前不处理并发版本冲突。

任何一步失败立即停止，不得以“前端已展示按钮”为由跳过。

## 5. 错误码建议

| 错误码 | HTTP | 含义 |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | 参数或字段校验失败 |
| `UNAUTHENTICATED` | 401 | 未登录或令牌无效 |
| `FORBIDDEN` | 403 | 无功能权限、数据范围或节点权限 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在或按安全策略不可见 |
| `TASK_STATUS_CONFLICT` | 409 | 任务当前状态不允许该操作 |
| `OPINION_STATUS_CONFLICT` | 409 | 意见当前状态不允许该操作 |
| `VERSION_CONFLICT` | 409 | 乐观锁/并发冲突 |
| `DUPLICATE_REQUEST` | 409 | 幂等键与请求内容冲突 |
| `EXTERNAL_SERVICE_UNAVAILABLE` | 503 | 文件、邮件、身份等外部服务不可用 |

## 6. 契约治理

- 所有接口在实现前补充 OpenAPI 定义和接口测试。
- 破坏性字段删除、枚举改名、语义变化必须创建新版本或完成兼容窗口评估。
- Controller 只做 DTO 转换和调用应用服务；不得接收前端传入的角色、操作者或最终状态作为可信事实。
