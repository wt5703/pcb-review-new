# PCB 评审平台后端接口设计

## 1. 通用约定

- 基础路径：`/api/v1`。
- 认证：由公司统一身份认证接入；Controller 从安全上下文读取当前用户，不接受客户端传入 `operatorId`。
- 写请求建议带 `Idempotency-Key`；响应带 `traceId`。
- 分页请求：`page`（从 1 开始）、`size`（最大值由配置控制）、`sort`。列表响应包含 `items`、`page`、`size`、`total`。
- 所有接口使用 DTO，不直接暴露数据库实体。枚举同时返回 `code` 和可展示的 `name`。

统一错误响应：

```json
{"code":"TASK_STATUS_CONFLICT","message":"当前任务状态不允许此操作","traceId":"..."}
```

## 3. 核心请求约束

### 3.1 创建任务 `POST /tasks`

请求包含任务名称、项目名称、评审类型、设计者、设计名称、描述、期望完成时间、PCB 类型（如适用）、评审角色及初始关联文件。创建草稿可缺少提交必填项；提交接口必须做完整校验。

### 3.2 分配人员 `POST /tasks/{id}/reviewers`

请求包含 `reviewRole`、`reviewerIds`、`comment`。应用服务校验：任务状态允许分配、当前用户有对应分配权限、人员有效、无重复关系。多人分配必须分别保存处理关系。

### 3.3 意见答复与确认

答复请求包含 `replyType`、`reason`、`fileVersionId`（可选）。确认请求包含 `result`、`comment`。服务端校验意见当前状态、答复人资格、确认人资格以及关联文件归属；不得由客户端直接提交目标意见状态。

### 3.4 文件接口

上传采用“两步式”：后端签发经授权的上传凭据/会话，客户端上传至公司文件服务，再回调或提交文件元数据进行关联。后端计算/验证 MD5、业务文件版本链和最新版本切换。下载接口只返回短期签名 URL，不透传永久存储地址。

## 4. 授权校验模式

每个写接口按固定顺序校验：

1. 用户已认证且账号有效。
2. 用户具备对应功能权限。
3. 用户对目标任务/意见/文件处于允许的数据范围。
4. 当前任务状态和节点允许该操作。
5. 用户是该节点的被分配处理人，或具有 PRD 明确的管理/结束权限。
6. 请求版本号与持久化版本一致。

任何一步失败立即停止，不得以“前端已展示按钮”为由跳过。

## 5. 错误码建议

| 错误码 | HTTP | 含义 |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | 参数或字段校验失败 |
| `UNAUTHENTICATED` | 401 | 未登录或令牌无效 |
| `FORBIDDEN` | 403 | 无功能权限、数据范围或节点权限 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在或按安全策略不可见 |
| `TASK_STATUS_CONFLICT` | 409 | 任务当前状态不允许该操作 |
| `OPINION_STATUS_CONFLICT` | 409 | 意见当前状态不允许该操作 |
| `VERSION_CONFLICT` | 409 | 乐观锁/并发冲突 |
| `DUPLICATE_REQUEST` | 409 | 幂等键与请求内容冲突 |
| `EXTERNAL_SERVICE_UNAVAILABLE` | 503 | 文件、邮件、身份等外部服务不可用 |

## 6. 契约治理

- 所有接口在实现前补充 OpenAPI 定义和接口测试。
- 破坏性字段删除、枚举改名、语义变化必须创建新版本或完成兼容窗口评估。
- Controller 只做 DTO 转换和调用应用服务；不得接收前端传入的角色、操作者或最终状态作为可信事实。
