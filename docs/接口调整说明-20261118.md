# 2026-11-18 接口及流程调整

本次对应邮件及评审流程的第 1～5 项需求，请求路径和参数保持兼容。

1. 邮件先确定实际收件人，再合并抄送，按去除首尾空白、忽略大小写的邮箱去重，并从抄送中剔除实际收件人。
2. 任务评审角色包含 `STRUCTURE_EXPERT` 时，所有任务邮件追加 `reviewer_whitelist.roles` 包含完整角色码 `STRUCTURE-LEADER` 的有效人员。判断使用整个任务的角色及人员分配，包含尚未开启的结构角色。保留原有硬件开发部及 EMC 领导抄送规则；空邮箱和已删除人员不参与。
3. PCB 首阶段完成待办支持 `PCB_EXPERT`、`EMC_EXPERT` 和 `HARDWARE_EXPERT`。原理图专家阶段也按全部已分配专家检查完成情况。
4. 设计者推进流程要求对应阶段的意见全部闭环，且全部已分配评审人明确调用 `POST /tasks/{taskId}/opinions/no-opinion` 点击评审完成。意见已通过不能代替该操作。有意见和无意见都使用此接口；同一人兼任工艺、结构角色时须分别提交两个来源。互检固定项及额外意见共用一次完成。未完成人员继续出现在意见汇总的 `unsubmittedReviewers` 中。
5. `START_PCB_PROCESS_REVIEW`、`START_PCB_STRUCTURE_REVIEW` 及同时开启两者时，不要求已上传工艺或结构文件；可后续上传。`START_PCB_MATUAL_ASSIGNMENT` 仍检查最新工艺、结构文件，终版及原理图文件校验保留。

评审完成状态保存在独立的 `review_submission` 表。退回或重新开启阶段时清除对应阶段的完成状态，保留所有意见、答复和确认历史；新提意见会使该人员对应来源的完成状态失效。删除任务同步删除完成记录。

## 数据库部署

增量变更统一放在 [upgrade.sql](database/upgrade.sql)。已有数据库在部署前按当前表结构执行尚未应用的语句，已执行旧版升级脚本的部分不要重复执行。全新数据库使用更新后的 `ddl.sql`。

升级脚本只为旧版本已从待办中移除、且对应来源意见全部闭环的人员回填完成记录。仍在待办中的人员必须明确点击完成；有草稿或未闭环意见的不回填。历史回填的时间使用该来源意见的最后更新时间，后续完成时间使用实际操作时间。
